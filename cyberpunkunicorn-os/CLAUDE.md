# CyberUnicorn 5000™ (project dir: cyberpunkunicorn-os)

Our own firmware for the ESP32-2432S028 "Cheap Yellow Display" stacked on an
NMTech NM-RF-HAT: Bruce underneath, our branding, patches and apps on top. Goal
and roadmap: [`SCOPE.md`](SCOPE.md). Started 2026-10-19 from the `nm-rf-hat/`
build (copied, not shared — that project stays as the known-good fallback).

## Pinned toolchain

- Bruce: tag **1.16.1**, env **`CYD-2432S028`** (cloned to `.bruce/`, gitignored)
- PlatformIO **6.2.0**, esptool **5.4.0** — in `.venv/`, created by `build.sh`
- OS identity: `OS_NAME` / `OS_VERSION` at the top of `build.sh` ("CyberUnicorn 5000", 0.1.0).
  The display font has no ™ glyph: screens draw a superscript "TM"; serial prints a real ™.
- Build: `./build.sh` → `build/app.bin`, `build/full.bin`
- Flash: `./flash.sh` (app only, keeps on-device settings) or `./flash.sh --full`
- Remote: `./remote.sh` mirrors the screen to http://localhost:8765 over serial
- Test: none automated. A clean build is the minimum bar; confirm on the device
  (`info` over serial must print `CyberUnicorn 5000™ v<version>`; `hat` runs the module probe).

## How changes are made

Never leave hand edits in `.bruce/` — `build.sh` resets it to pristine upstream
on every run. To change Bruce: apply the patches, `git -C .bruce add -A`, edit,
`git -C .bruce diff > patches/NNNN-name.patch` (only your new change, one
concern per patch), then `git -C .bruce reset`. Our own apps go in `apps/<name>/`
as plain source, copied in by `build.sh` — never inside a patch.
User-tunable values go in `boot.conf` → `-D` macros via `PLATFORMIO_BUILD_FLAGS`.

## Patches (applied in order by build.sh)

- `0001` boot text → macros (`BOOT_TITLE`/`BOOT_TAGLINE`)
- `0003` radio defaults for the hat: `rfModule=CC1101_SPI`, `rfidModule=PN532_I2C`
- `0004` autostart (`STARTUP_APP`) + menu trim (`TRIM_UNUSED_MENUS`)
- `0005` OS identity: `OS_NAME`/`OS_VERSION` in `info`, `help`, Device Info, status bar
- `0006` registers our apps: includes `cyber_apps/apps.h` in the main menu and CLI
- `0007` boot hook: `boot_screen_anim()` runs `unicornBootScene()` (apps/boot)
- `0008` rainbow skin: Bruce's shared drawing code (status bar, borders, titles,
  option lists, submenus, stripes, progress bars, file list, touch footer, main-menu
  icon colours) calls `apps/ui/rainbow.h`; default colours hot pink / cyan
- `0009` de-brand: every user-visible "Bruce" (Wi-Fi/BLE names, AP + web defaults,
  mDNS `unicorn.local`, NDEF/QR defaults, pwnagotchi, GPX) + rainbow web UI CSS

(No 0002: the nm-rf-hat cat scene was dropped for the unicorn.) Macros in 0003–0004
keep their `NM_` prefix from `nm-rf-hat/`; renaming them is churn.

**Deliberately still "Bruce"** — for compatibility or the AGPL credit, not oversight:
`Filetype: Bruce …` file headers and `/Bruce*` SD folders (saved captures keep
loading), `bruce.conf` / `bruceConf.json`, the web API's `BRUCE_VERSION` key, the
wardriving CSV format, `/bruce` dev-proxy paths in the web JS, the CC1101 wiring
QR links (they point at upstream docs), and one "Based on Bruce" credit in
Device Info / `info` / `help`. Bruce is AGPL-3.0: keep that credit and keep the
source published if builds are distributed.

## Our apps (`apps/`, copied to `src/cyber_apps/`)

- `apps.h` — registry: menu members, menu order, CLI commands. Add new apps here.
- `hat/` — **Hat**: probes which hat module is live (I2C 0x24 for PN532, CC1101
  PARTNUM/VERSION, nRF24 SETUP_AW, RX-pin noise for IR/433). CLI: `hat`.
  Verified: PN532 detected with DIP 3 on. IR/433 is a heuristic — unverified.
- `lightshow/` — **Light Show**: 18 scenes (11 "mystic" + 7 classic) for an 8x8
  WS2812B panel, mirrored live on screen, so it works with no panel too. Ported
  from the CircuitPython Unicorn OS launcher (`scenes.py`/`lightshow.py`, 2026-10-17,
  in a Claude scratch workspace, not this repo). Driver: core 3.3.9 RMT
  (`rmtInit`/`rmtWrite`, rgbLedWrite timings). Settings in NVS namespace
  `lightshow` (pin, zigzag, rotate, level, scene). Default data pin **27** (Grove
  SDA): needs DIP 1-5 OFF, and the app refuses to start if a hat module answers.
  Panel V+ needs its own 5 V; brightness capped at 40%. Not yet tested with a panel.
- `slideshow/` — **Slideshow**: plays `.jpg/.jpeg/.png/.bmp/.gif` from `/slides`
  (SD, else LittleFS), sorted by name. Stills hold for the slide time, GIFs play once
  (15 s cap), as in the launcher's `slideshow.py`. NEXT/SEL next, PREV back, ESC exit.
  NVS `slideshow` (`ms`, `loop`). Uses Bruce's `drawImg`/`showJpeg` and its `Gif`
  class frame by frame. JPEGs are loaded whole into RAM: oversized ones are skipped
  with a caption. No scaling: 320×240 or smaller. The LED-panel mirror was not ported.
  CLI: `slides` lists what it would play.
- `boot/` — unicorn boot scene. `unicorn_sprite.h` is generated by
  `assets/make_unicorn.py` (also writes preview PNGs); edit the grids there.
- `ui/` — rainbow helpers used by patch 0008.

**Persisted-config gotcha:** compile-time defaults only apply when the key is
absent from the on-flash config (LittleFS at 0x3d0000). App-only flashing keeps
it; change settings live over serial (`settings startupApp WebUI`, …) or the menu.
This bites the skin too: colours, the Wi-Fi AP name/password and web UI login
already saved on a unit keep their old values until changed in Config.

## Grounding rules

Bruce moves fast. Before using any Bruce API or config key, grep `.bruce/` at
the pinned tag — not memory, not `main`. Board pins:
`.bruce/boards/CYD-2432S028/CYD-2432S028.ini`. New menu apps subclass
`MenuItemInterface` (`include/MenuItemInterface.h`) and are listed in
`src/core/main_menu.cpp`.

## Hardware (verified on this unit unless marked)

| Thing | Value |
|---|---|
| MCU | ESP32-D0WD-V3 rev 3.1, 240 MHz, 4 MB flash |
| USB-serial | WCH CH340 (VID 0x1A86), macOS built-in driver, shows as `/dev/cu.usbserial-*` |
| Display | 2.8" 320×240 TPM408-2.8, ILI9341 driver, resistive touch |
| Hat | NM_RF_hat V1.0: CC1101, nRF24, PN532 (I2C), IR, 433 MHz OOK |
| Shared pins | SPI 18/19/23; CS 27, GDO0/CE 22; I2C SDA 27 / SCL 22 (Grove + PN532) |
| SD | CYD slot, SPI CS 5 (hat slot reaches it via a micro-SD extender) |

## Constraints that bite

1. **USB-C ↔ USB-C does not power the CYD** (no CC pull-downs). Use USB-A →
   USB-C via an adapter, into the **CYD's** port. The hat's port powers it but
   has no data — the board lights up and never appears on USB.
2. **Serial above 230400 baud corrupts.** `flash.sh` uses 230400; the CLI is 115200.
3. **Opening the serial port reboots the board**, and replies can lag several
   seconds behind the command — wait for boot, then read for a while.
4. **DIP switch: only one of 1–5 ON** (1 CC1101, 2 nRF24, 3 PN532, 4 IR,
   5 433 OOK; 6 = battery). Everything shares pins 22/27. I2C sensors can share
   the bus with the PN532, not with the SPI radios.
5. **Flash budget:** app partition 0x10000–0x3cffff (3.75 MB). ~315 KB was free at
   0.1.0. Check `build/app.bin` size on every app added.
6. **SD:** Bruce mounts FAT32 only. The 2 TB AliExpress card is fake and never mounts.
7. Bruce's `patch.py` can half-patch `libnet80211.a` in the shared PlatformIO
   cache. Symptom: `cannot find -lnet80211`. Fix: rename `libnet80211.a.old`
   back, delete `lib/.patched`, rebuild with `.venv/bin` on PATH (build.sh does this).
8. Boot tagline is drawn in the touch footer; ~26 chars fit at 320 px.

## Recovery

- Last nm-rf-hat flash (Bruce 1.16.1-nm + settings), full 4 MB:
  `nm-rf-hat/backups/cyd-flash-2026-10-19-bruce-v1.16.1-nm.bin` (gitignored, local only).
- Factory LVGL demo: `~/Downloads/cyd_factory_backup_2026-09-30.bin`.
- Restore: `.venv/bin/esptool --chip esp32 --port <port> --baud 230400 write-flash 0x0 <file>`.

## Transmit

CC1101/nRF24/433 OOK/IR can transmit. Keep TX to hardware you own and within
your local band rules.
