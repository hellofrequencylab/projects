# Cyber Box Mesh: project handoff (brainstorm)

Oct 3, 2026 · Daniel Tyack

> **Status: loose brainstorm.** The owner's framing: "don't take it seriously."
> Everything below is a starting point for discussion, including the
> "decisions". None of it is a spec. Ranges, costs and prior-art notes were
> written from memory and have not been checked.

## The vision

A fun, community-built backup internet: DIY cyber boxes that link to each other
Wi-Fi to Wi-Fi, store people's notes and files, and share them automatically
with any box in range. No ISP, no accounts, no central server.

The network runs on its own open protocol and can bridge to the regular
internet, but never depends on it. The same protocol runs on a $10 board or a
server room, and drive size doesn't matter. The community is half the product:
people learn to build, flash and place their own boxes, and every box placed
grows the network.

## Ideas so far (the owner hasn't pushed back on these, but they aren't settled)

| Area | Idea | Why |
|---|---|---|
| Core link | Wi-Fi to Wi-Fi via ESP-NOW in Long Range mode | $5–10 ESP32 boards; no AP, pairing or IP |
| Heart module | Every box has the same ESP32 radio and firmware; Pi or server boxes attach it over USB | One radio to learn, flash and debug |
| Serving people | Every box is also a Wi-Fi hotspot with a captive-portal web page | Any phone works, iPhone included, with no app |
| Other transports | Pluggable: 802.11s, BLE, LoRa, USB sneakernet, internet | "Port to the internet" is one more pipe |
| Transport layer | Build on Reticulum and add an ESP-NOW interface to it | IP-free, transport-agnostic, small-hardware friendly |
| Data model | Signed, content-addressed blobs; identity = keypair | Any node can verify content; no account server |
| Sync | Set reconciliation ("what do you have that I don't?") | Costs bytes, works in a 30-second encounter |
| Traffic scope | Text, notes, files, maps, boards, messages. No video | Realistic for 250–500 kbps hops |

### Hardware tiers (approximate costs)

Each box announces what it can do: storage, whether it relays, and which circles it keeps.

| Tier | Reference build | Cost | Role |
|---|---|---|---|
| Pocket beacon | ESP32 (e.g. S3) + microSD + LiPo + small antenna | $10–25 | Relay, hotspot, indexes and small items; runs days on a battery |
| Window / rooftop | ESP32 heart + external antenna + solar + enclosure | $30–60 | Long-range neighborhood relay |
| Home box | Pi Zero 2 W / Pi 5 + SSD + ESP32 heart over USB | $40–120 | Archive, search, web UI, 802.11s to other Linux boxes |
| Hub | Linux server + one or more ESP32 hearts | varies | Big archive; bridge to the internet and other transports |

Range to plan around, all unverified until field-tested: about 50–100 m per hop
in a city with stock antennas, and around 1 km line-of-sight with ESP-NOW LR
and a decent antenna.

## Prior art to study (from memory; check each project's docs before relying on it)

| Project | Gets right | Borrow | Fell short |
|---|---|---|---|
| Reticulum | IP-free, transport-agnostic, encrypted, small hardware | The transport layer | No storage or social layer; niche audience |
| Meshtastic | ESP32 + LoRa; huge DIY community; web flashing | Onboarding, web flasher, node map | Messages only |
| Secure Scuttlebutt | Offline-first gossip; signed logs | Social model, circles | Hard to use; logs grew forever |
| Willow / Earthstar | Efficient two-device sync; permissions | Set reconciliation, capabilities | Young ecosystem |
| IPFS / BitTorrent | Content addressing | Blob IDs, verification | Assumes the internet |
| Freifunk / NYC Mesh | City-scale volunteer Wi-Fi mesh | Rooftop guides, governance | Needs Linux routers; carries IP, not content |
| PirateBox / LibraryBox | Walk-up hotspot file sharing | The browse experience | Boxes never synced |

## Hard problems (ranked by how much each shapes the design)

| Problem | Why it matters | Current answer |
|---|---|---|
| Phones | iOS barely allows background BT or Wi-Fi | Boxes do the syncing; phones join a hotspot |
| Abuse in the commons | Malware and illegal content; relay operators may face legal exposure | Web-of-trust feeds, per-node refusal, shared blocklists; circles are opaque to relays |
| Throughput and range | ESP-NOW LR ≈ 250–500 kbps per hop | The index travels fast, big files trickle |
| One channel at a time | A hotspot and ESP-NOW on one ESP32 must share a channel | A network-wide default channel in the spec |
| No deletion | Synced content is out there for good | Warn in the UI; tombstones that honest nodes respect |
| Lost keys | Lose your key, lose your identity | Social recovery (e.g. 3 of 5 friends), designed early |
| Radio rules | 2.4 GHz power is capped by law | Build guides teach legal limits per region |

## Community model

1. **Flash:** one-click browser install over Web Serial, no toolchain.
2. **Build:** open hardware (KiCad, 3D-printable enclosures, parts lists).
3. **Place:** a live node map.
4. **Learn:** a path from "flash your first box" to "write a plugin," plus build-night kits.
5. **Govern:** a public, versioned spec.

Proposed licensing, for the owner to confirm: spec CC BY, firmware GPL,
hardware CERN-OHL, docs CC BY-SA.

## Roadmap (no dates)

1. **Spec v0.1.** Identity, ESP-NOW frame, sync handshake, blob format, keying. *Done when:* two people could write compatible firmware from the spec alone.
2. **Two boxes, one note.** *Done when:* a note typed on a phone joined to box A shows on a phone joined to box B, with no internet.
3. **Three-hop relay.** *Done when:* a note crosses three boxes in a field test, with the range written down.
4. **Circles.** *Done when:* a relay holds a circle's content and cannot read it.
5. **Home box.** Pi + ESP32 heart + Reticulum. *Done when:* a Pi box and a beacon sync both ways.
6. **Browser flasher + build guide.** *Done when:* an outsider builds and flashes a box from the guide alone.
7. **Internet bridge + node map.** *Done when:* two meshes in different cities share a public space.
